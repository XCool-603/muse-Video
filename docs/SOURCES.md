# 采集源与平台清单

> **数据实测于 2026-09-30。** 采集站轮换非常频繁，本文的可用性结论会过期。
> 建议定期复测（方法见[第七节](#七排查方法)），不要长期依赖这份快照。

---

## 一、总览

平台分两类：**官方平台**（站点自己提供接口）和**第三方采集源**（苹果CMS V10 采集站）。

2026-09-30 实测 **46 个**候选采集接口（不含原有的 6 个启用源），结果：

| 结果 | 数量 | 去向 |
|------|------|------|
| ✅ 可用、内容干净、且与其他源不重复 | **6** | 已写入默认配置 |
| ⚠️ 响应 200 但返回网页（假活） | 4 | 见 [5.1](#51-返回网页假活) |
| ❌ 连不上 / 非 JSON / 403 | 21 | 见 [5.2](#52-连不上--非-json--403) |
| ⚠️ 能连上但搜索恒为 0 条 | 1 | 见 [5.3](#53-能连上但零产出) |
| ⚠️ 与现有源是同一上游 | 4 | 见 [5.4](#54-与现有源重复同一上游) |
| ⛔ 因返回内容不合规而排除 | 10 | 见 [5.5](#55-因内容不合规排除) |
| **合计** | **46** | |

当前线上：**3 个官方平台 + 12 个第三方采集源**，全库 6460 部短剧。

## 二、官方平台

这一类是站点自己提供、自己公开的接口，授权关系最清晰，应当优先使用。

| 平台 | 编码 | 域名 | 接口性质 | 入库 | 可播性 |
|------|------|------|---------|------|--------|
| 黄果短剧 | `huangguo` | huangguodrama.ai | 站点在 `robots.txt` 里显式 `Allow` 了 `/api/agent/v1/`，并发布 OpenAPI 3.1.0 规范 | 513 部（其中 187 部有正片） | **明文 MP4**，无 DRM / 无鉴权 / CORS 全开 |
| 红果短剧 | `hongguo` | hongguoduanju.com | 官方 H5，目录为服务端渲染可索引 | 24 部 | ❌ 视频为 MP4 CENC（AES-128 CTR）DRM 加密，服务端无法解密 |
| 黄豆短剧 | `huangdou` | hddj.tv | 官方站点 | 0（开发环境不可达） | 免费集 m3u8 无鉴权可播；**付费集有服务端权益校验**（JWT HS384 + DB） |

### 黄果短剧（最干净的一个）

官方公开的 catalog API，限流 60 请求/IP/分钟（适配器按 50 控制）：

```
GET /api/agent/v1/openapi/                       → 规范本身
GET /api/agent/v1/search/?page=N&limit=20        → 目录（total=513，官方上限 limit=20）
GET /api/agent/v1/titles/{id}/                   → 详情
GET /api/agent/v1/titles/{id}/episodes/?page=N   → 分集
```

**两个必须知道的坑**（2026-09-30 实测）：

1. **513 部里只有 187 部有正片。** 其余是 30 秒片头（`opening_clip`）或 33 秒预告（`trailer`）。
   判据是目录接口的 `full_episode_count`（实测与 `media_type=episode` 的条数完全一致）。
   **不要用 `catalog_episode_count`**（声明集数，把片头也算进去）或 `published_episode_count`（同样含片头）。
2. **分集接口的 `media_type` 必须区分。** 实测分布：`episode` 正片约 85 秒 / `opening_clip` 片头正好 30 秒 /
   `trailer` 预告约 33 秒 / `short_film` 短片。不加区分会把「106 条 30 秒片头」展示成「106 集正片」。

### 黄豆短剧的付费集

付费集在服务端有权益校验，同端点对未购买请求返回 404。适配器**如实标记 `IsLocked` 并在取流时抛明确异常**，
不做绕过。逆向文档给出的绕过方式是改走第三方线路 `psfxhhox.top`（与 hddj.tv 并非同一站点），
那属于接入另一个未授权源，不在适配器范围内。

## 四、采集协议（苹果CMS V10）

国内影视站最常用的开源 CMS，其采集接口是事实标准。**只需在 `apple-cms-sources.json` 里填一个 api 地址
即可接入新源，不用改任何代码。**

### 端点

| 用途 | 请求 |
|------|------|
| 关键词搜索 | `{api}?ac=detail&wd=关键词&pg=N` |
| 按 ID 取详情 | `{api}?ac=detail&ids=ID` |
| 分类表 | `{api}?ac=list` |
| 按分类拉取 | `{api}?ac=detail&t=<type_id>&pg=N` |
| 日榜 / 周榜 | `{api}?ac=detail&pg=1&h=9` / `&h=8` |

**每页固定返回约 20 条**，由源站决定，请求方只能裁剪不能放大。翻页用 `pg=N`，实测各源均有效
（`pg=1/2/3` 零重复）。

### 字段映射

| 源站字段 | 含义 | 站内去处 |
|---------|------|---------|
| `vod_id` | 短剧 ID | `PlatformDramaId` |
| `vod_name` | 标题 | `Title` |
| `vod_pic` | 封面 | `CoverUrl` |
| `vod_blurb` / `vod_content` | 简介 | `Description` |
| `vod_remarks` | 更新状态（含「完」即完结） | `Status` |
| `vod_score` | 评分 0-10 | `Rating` |
| `vod_hits` | 播放量 | `PlayCount` |
| `vod_play_from` | 播放源标识 | — |
| `vod_play_url` | 剧集列表 | `Episodes` |

### `vod_play_url` 的三层分隔符

```
第1集$url1#第2集$url2$$$第1集$urlB1#第2集$urlB2
└──── 播放源 A ────┘└──── 播放源 B ────┘
```

- `$$$` 分隔**多个播放源**（同一部剧的不同线路）
- `#` 分隔**剧集**
- `$` 分隔**集名与地址**

适配器会**优先挑含 `.m3u8` 的那一组**。实测 `ffzy` / `dyttzy` 的第 0 组是 `/share/` 形式（非 m3u8），
第 1 组才是 m3u8，现有逻辑选对了。

> ⚠️ **已知缺口**：若首个 m3u8 不可播，目前**不会自动回退到其他播放源组**。
> 这是提升可播率最直接的一个改进点。

> 但一律 `enabled: false`，默认不参与聚合。
> 它们此前曾以 `enabled: true` 留在未提交的工作区文件里（配置与本节结论自相矛盾，
> 重启就会被真实聚合进搜索），现按「可配置但默认关闭」处理。
> **要启用其中某一个**：把该条目的 `enabled` 改成 `true` 并重启后端 ——
> 管理后台的平台开关只对「已注册适配器」的源有效，对 `enabled=false` 的源点了没用。
> `excludeAdult` 只是兜底，不是保证；启用前请自行核验内容合规性。

## 六、地区限制（重要，且极易误判）

**源站 CDN 会按 IP / 地区整站拒绝，同一批源在不同网络下结论完全相反。**

2026-09-30 从一台**美国机房 IP**（38.14.209.58）实测 m3u8 直连：

| 结果 | CDN |
|------|-----|
| 403（连根路径都 403） | ppqrrs.com（无尽）、zuidazym3u8.com（最大）、bdzybf22.com（百度）、bfeng10.com（暴风）、cdnlz12.com（量子） |
| 200 正常 | ryplay16.com（如意）、hongniuzy2（红牛）、mdzyapi（魔都） |

**已排除请求头因素**：无头 / 浏览器 UA / 加采集站 Referer / 加 CDN Referer，四种组合结果完全一致。
对照实验确认通用公网 HLS 测试流正常 200，说明本机网络本身没问题。

> **结论：可播性必须在实际部署机上验证，不能凭本文或任何境外节点的测量下结论。**
>
> ```bash
> curl -I '<某一集的 m3u8 地址>'   # 看是否 200
> ```

同理，**「入库量」和「可播量」是两件事**：本文所有「实测入库」数字都是按接口返回统计的，
不代表在你这台机器上都能播。

## 七、排查方法

### 怎么找到一个真正带短剧的新源

别盲扫。**从已知有短剧的站点顺藤摸瓜**：

1. 打开一个短剧站的播放页，查看页面里的 `player_aaaa` 配置
2. 其中的 `from` 字段标识了内容来自哪个采集源
3. 例如某站 `from` 是 `bfzym3u8` → 对应「暴风资源」`bfzyapi.com`

比对着 46 个域名一个个试要高效得多。

### 怎么判断一个源有没有短剧

```bash
# 1) 能连通、返回合法 JSON 吗
curl -s 'https://<域名>/api.php/provide/vod/?ac=detail&wd=短剧&pg=1' | head -c 300

# 2) 看分类表里有没有短剧分类（拿到 type_id）
curl -s 'https://<域名>/api.php/provide/vod/?ac=list' | python -c "import sys,json;print([f\"{c['type_id']}={c['type_name']}\" for c in json.load(sys.stdin).get('class',[])])"

# 3) 验证 type_id 是否真生效（关键！返回全站几万条说明被忽略）
curl -s 'https://<域名>/api.php/provide/vod/?ac=detail&t=<type_id>&pg=1' | head -c 200

# 4) 验证翻页是否有效（pg=1 与 pg=2 是否零重复）
```

**注意**：第 1 步返回 200 且以 `<` 开头**不代表可用**，见 [5.1](#51-返回网页假活)。

## 八、播种容量与限流

「平台很多但短剧很少」的常见原因是**播种只读了第一页**。

### 关键参数（`apple-cms-sources.json` 的 `AppleCms` 段）

| 参数 | 默认 | 说明 |
|------|------|------|
| `bootstrapKeywords` | 8 个 | 播种关键词：短剧/霸总/重生/穿越/战神/甜宠/闪婚/逆袭 |
| `bootstrapLimitPerKeyword` | 20 | 每关键词每页取多少条（采集站每页固定约 20） |
| `bootstrapPagesPerKeyword` | 5 | 每个关键词翻几页 |
| `bootstrapPageDelayMs` | 300 | 页间间隔（毫秒） |
| `bootstrapMaxCandidatesPerSource` | 0 | 单源候选上限；0 = 用旧算法 `max(bootstrapMaxPerSource, maxCatalogPages×20)` |
| `bootstrapTotalTimeoutSeconds` | 1800 | 首次播种总超时，超时后剩余平台会被跳过 |

### 实测容量

| 配置 | 单源去重后 |
|------|-----------|
| 8 词 × 5 页（当前） | 无尽 659 / 暴风 699 / 如意 571 |
| 20 词 × 3 页 | 1071 / 1130 / 798 |
| 20 词 × 5 页 | **1593 / 1684 / 1150** |

**必须加页间节流**：8 条关键词链并行翻 5 页会在短时间内对同一源打出约 40 个请求，实测会被限流——
暴风返回 429，**无尽直接全部超时并把该源整轮播种打废（86 秒只收到 80 部）**。
加 300ms 间隔后无尽 6.9 秒收到 600 部。日志里会看到
`采集源 XX 请求失败（由于线程退出或应用程序请求，已中止 I/O 操作）`，那就是被限流了。

## 九、维护建议

1. **定期复测**。采集站轮换频繁，本文结论会过期。管理后台「平台源管理」可以逐个点「同步」探活。
2. **优先官方接口**。黄果这类站点自己公开、`robots.txt` 明确 Allow 的接口，授权关系最清晰。
3. **入库量 ≠ 可播量**。看到某个源入库很多先别高兴，按 [第六节](#六地区限制重要且极易误判) 在部署机上验一次。
4. **注意 `t` 参数是否真生效**，填错会让「上新」拉回全站电影综艺。
5. **加源前先核验内容范围与合规性**。第三方采集站内容非本系统提供，
   运营方需自行确保拥有相应的合法版权或授权。
